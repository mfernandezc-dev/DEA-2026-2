## Contrato

La tabla de endpoints y los ejemplos se centralizan en el README para evitar
duplicación. Listados paginados heredados (`count`, `next`, `previous`, `results`,
cinco elementos por página). Cada producto incluye categoría completa de lectura,
con `category_id` exclusivamente de escritura. Precio decimal como cadena.
Imagen obligatoria al crear; opcional al actualizar con PUT o PATCH.
JSON, multipart y form-urlencoded aceptados. Borrado de categoría usada: 409.
La API raíz amplía sus enlaces de tres a cinco recursos; se actualizó únicamente
esa expectativa de la prueba `quiz`, sin alterar sus endpoints ni sus vistas.

## Capa de servicios

Solo `services/api.js` importa Axios y crea una instancia. El módulo heredado
`api/client.js` reexporta esa misma instancia. No se modificaron componentes.
Una factoría comparte las cinco operaciones de cada servicio y devuelve los
datos del servidor; `remove` devuelve `undefined`. PATCH es el método de
actualización predeterminado; `{ replace: true }` usa PUT.
`getAll(params, config)` devuelve el sobre paginado, no una lista agregada.
Los errores Axios originales conservan status, detalles de validación y señales
de cancelación. `getApiErrorMessage` permite presentar un mensaje común.
FormData se entrega intacto a Axios, sin fijar Content-Type global.

## Seguridad y protección

Es una demostración académica con escritura anónima (AllowAny heredado), no
configuración de producción. Se ejecuta solo en localhost. Antes de exponerla
hay que implementar autenticación, permisos y una configuración de despliegue.
Las pruebas Django usan base y media temporales. La integración real utiliza
nombres UUID y elimina exclusivamente sus registros e imágenes.
La línea base de Git, datos y medios está en `VERIFICACION.json`.

## Ajustes y problemas resueltos

- Se compusieron ambos routers para que la raíz `/api/` descubra los cinco
  recursos; la prueba heredada que esperaba tres enlaces se adaptó a esta
  ampliación intencionada, conservando las demás pruebas.
- El cliente Axios anterior se convirtió en una reexportación, evitando una
  segunda instancia y preservando el módulo de exámenes.
- Una prueba nueva consultaba Accept en `headers.common` en vez del encabezado
  explícito configurado. Se corrigió la prueba y se verificó además el Accept
  realmente recibido por HTTP. La ejecución definitiva pasó las 42 pruebas.
- Django no elimina automáticamente los archivos al borrar productos; la
  integración registra las rutas de sus propias subidas y las elimina
  explícitamente, sin tocar los PNG originales.
